# 0004 — Astro 7, not Astro 5

Status: accepted
Date: 2026-09-12
Supersedes: the "Astro 5" instruction in the build brief; `docs/02-project-structure.md` §1

## Context

The stack was specified as Astro 5, and the scaffold was initially built on
`astro@5.18.2`. `npm audit` on that install reported one critical and one high
advisory. The affected range is `astro <=7.2.7` — every 5.x and 6.x release is
included and no fix was backported. The patched versions are 7.2.8 and later.

Ten advisories sit in that range. Most need a feature this site does not use:
the XSS reports require `define:vars`, spread props, `transition:*` directives,
view-transition animation properties, or attacker-controlled slot names; the
host-header SSRF requires SSR; the authorization bypass requires a configured
`base`. The two with a plausible path here were the `sharp`/libvips AVIF RCE,
which runs at build time over committed images, and a Windows-only dev-server
file read in `esbuild`.

So the practical exposure was low, but it was not zero, and starting a
greenfield site two majors behind on a version with unpatchable criticals is a
poor opening position for something that has to be maintained for years.

## Decision

`astro@7.3.2`. `npm audit` reports zero vulnerabilities.

## Consequences

Three forced changes, all of them consequences of Astro 6 and 7 rather than
preferences:

1. **Content config moves to `src/content.config.ts`.** Astro 6 removed legacy
   content collections and turned `src/content/config.ts` into a build error.
   The collection *directories* still live under `src/content/`; only the config
   file moved up one level. Every collection now declares a `loader`
   (`glob()` from `astro/loaders`).
2. **`z` comes from `astro/zod`, not `astro:content`.** The `astro:content`
   re-export is deprecated in 7.x and emits a hint per usage. `astro/zod` is a
   re-export of Zod 4 and needs no separate dependency.
3. **Node floor is 22.12.0.** Astro 6 dropped Node 18 and 20. `package.json`
   `engines` and the CI matrix both reflect this.

Other 7.x changes that did not require action here but will matter later:

- The Rust compiler is now the only compiler and rejects unclosed tags that the
  old one accepted silently.
- `compressHTML` defaults to `'jsx'`, so whitespace between inline elements is
  stripped by JSX rules.
- Markdown is processed by Sätteri rather than remark/rehype. Any remark or
  rehype plugin added later needs porting, or `@astrojs/markdown-remark`
  reinstalled deliberately.
- Vite 8. `@tailwindcss/vite` 4.3.3 declares `vite: ^5.2.0 || ^6 || ^7 || ^8`,
  so the Tailwind wiring in ADR 0003 is unaffected.

## Note on the audit

None of this touches the audit. Every finding in `docs/01-audit.md` is about
content, structure, conversion and SEO, and is platform-agnostic. This ADR is
purely about the build toolchain.
